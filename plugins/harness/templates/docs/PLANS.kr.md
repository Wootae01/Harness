# 계획 작성법

> 🇰🇷 한국어 번역본입니다. 정본(에이전트가 읽는 문서)은 [PLANS.md](PLANS.md)이며, 내용이 다르면 영어본이 우선합니다.

> 계획은 일급 아티팩트다. 리포에 저장되고, 버전 관리되고, 다음 세션의 에이전트가 이어받는다.

## 언제 실행 계획을 쓰는가

| 상황 | 계획 |
|---|---|
| 파일 1~3개, 한 세션 안에 끝남 | 머릿속/대화 안의 짧은 계획으로 충분 |
| 여러 세션, 여러 컨텍스트, 설계 판단, 마이그레이션 | `docs/exec-plans/active/`에 **실행 계획 작성** |

## 실행 계획 템플릿

```markdown
# <목표 한 줄>
상태: 🟨 진행 중 | 시작: YYYY-MM-DD | 관련 스펙: product-specs/...

## 목표와 완료 조건
- [ ] 검증 가능한 완료 조건 1
## 범위 밖
## 단계
- [ ] 1. ...
- [ ] 2. ...
## 진행 로그  (세션마다 맨 아래에 추가)
- YYYY-MM-DD: 한 일 / 막힌 것 / 다음 할 일
## 결정 로그
- YYYY-MM-DD: <결정> — 이유: ... / 기각한 대안: ...
## 발견한 부채  (→ tech-debt-tracker.md로 옮긴다)
```

## 규칙
- 세션이 끝나기 전에 **진행 로그**를 갱신한다. 다음 에이전트는 이 로그만 보고 이어서 작업한다.
- 계획이 끝나면 `completed/`로 옮기고 상태를 ✅로 바꾼다.
- 계획 도중 아키텍처 결정이 나오면 `design-docs/`로 승격하고 계획에서는 링크만 건다.
