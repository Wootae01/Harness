## 핵심 신념

1. **사람은 조정하고, 에이전트는 수행한다.** 사람의 시간과 주의력이 가장 부족한 자원이다.
   사람은 의도를 명시하고, 환경을 설계하고, 결과를 검증한다.
2. **에이전트가 볼 수 없는 것은 존재하지 않는다.** 결정, 합의, 취향은 리포 안의 버전 관리되는 텍스트로 남긴다.
3. **지도를 준다, 매뉴얼을 주지 않는다.** 진입점(CLAUDE.md)은 짧게 쓰고, 깊은 내용은 링크로 연결한다.
4. **불변식은 강제, 구현은 자유.** 경계는 중앙에서 정하고 그 안에서는 자율을 허용한다.
5. **규칙은 문서 → 코드로 승격된다.** 문서로 지켜지지 않는 규칙은 린트·테스트·훅으로 만든다.
6. **막힘은 신호다.** 에이전트가 실패하면 빠진 도구·가드레일·문서를 찾아 리포에 추가한다.
7. **수정은 싸고 대기는 비싸다.** PR은 작고 짧게 만든다. 불안정한 테스트는 막지 말고 추적해서 고친다.
   (단, 에이전트 처리량이 사람의 검토 능력을 넘어설 때 성립한다. 처리량이 낮으면 머지 게이트를 더 엄격하게 둔다.)

## 황금 원칙 (코드 일관성 유지 규칙)

> `/harness:cleanup`이 이 목록 기준으로 편차를 찾는다. 새 원칙을 추가하면 가능한 한 강제 수단도 함께 만든다.

| # | 원칙 | 이유 |
|---|---|---|
| G-1 | 직접 만든 헬퍼보다 **공유 유틸리티**를 우선한다 | 불변식을 한 곳에서 관리하기 위해 |
| G-2 | 데이터 모양을 **추측하지 않는다**. 경계에서 검증하거나 타입 있는 SDK를 쓴다 | 추측한 모양 위에 쌓은 코드는 조용히 깨진다 |
| G-3 | 리포 안에서 추론 가능한 의존성을 우선한다. 불투명하면 작은 부분집합을 직접 구현하는 것도 검토한다 | 에이전트가 검사·수정할 수 있어야 한다 |
| G-4 | 기존 패턴이 나쁘면 복제하지 말고 부채로 기록한다 | 에이전트는 있는 패턴을 그대로 복제한다 |
| G-5 | 새로 생긴 결정은 같은 PR에서 문서에 반영한다 | 문서와 코드의 드리프트를 막는다 |
